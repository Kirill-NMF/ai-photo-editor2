Problem Confirmed by EXPLAIN ANALYZE

The database query analysis revealed that PostgreSQL is performing separate sort operations for every query that orders by created_at:

Plain Text


Sort (quicksort) Memory: 26kB ← ❌ Separate sort operation!
  Sort Key: created_at DESC
  -> Seq Scan on projects
       Filter: (user_id = '425422')


Current queries in server/storage.ts:

•
Line 94: .orderBy(desc(projects.createdAt))

•
Line 130: .orderBy(desc(images.createdAt))

•
Line 147: .orderBy(desc(edits.createdAt))

All queries filter by user/project/image ID AND sort by created_at DESC, but the current indexes only cover the filtering part, not the sorting.

Performance Impact

Current situation (22 projects):

•
DB execution: 0.072ms

•
API response: 270-900ms

•
Sort operation: Minimal overhead for small dataset

Future situation (500+ projects):

•
DB execution: 20-50ms (sort operation becomes expensive)

•
API response: 300-1000ms+

•
Sort operation: 10-25x slower without composite indexes

GOAL

Add composite indexes that cover both filtering AND sorting in a single index, eliminating the need for separate sort operations.

Expected improvement:

•
Current (small data): Minimal improvement

•
Future (large data): 10-25x faster sorting

STRATEGY

Create composite indexes with columns in order: (filter_column, sort_column DESC)

This allows PostgreSQL to:

1.
Use the index to find matching rows (filter)

2.
Return results already sorted (no separate sort operation needed)

Critical: Use .desc() for createdAt because all queries use ORDER BY created_at DESC.

IMPLEMENTATION

Step 1: Update shared/schema.ts

Add composite indexes to each table. Important: Keep existing indexes and add new ones.




A. Projects Table

Add these lines to the index array (line 51-53):

TypeScript


export const projects = pgTable("projects", {
  id: serial("id").primaryKey(),
  userId: varchar("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  name: varchar("name"),
  createdAt: timestamp("created_at").defaultNow(),
}, (table) => [
  index("projects_user_id_idx").on(table.userId),  // ← Keep existing
  index("projects_user_id_created_at_idx").on(table.userId, table.createdAt.desc()),  // ← ADD THIS
]);


Why .desc()? Because the query uses ORDER BY created_at DESC:

TypeScript


// server/storage.ts line 94
.orderBy(desc(projects.createdAt))

COMPLETE CODE CHANGES

Here's the full updated shared/schema.ts with all changes:

TypeScript


import { sql } from "drizzle-orm";
import {
  index,
  integer,
  jsonb,
  pgTable,
  serial,
  text,
  timestamp,
  varchar,
} from "drizzle-orm/pg-core";
import { createInsertSchema } from "drizzle-zod";
import { z } from "zod";

// Session storage table - Required for Replit Auth
export const sessions = pgTable(
  "sessions",
  {
    sid: varchar("sid").primaryKey(),
    sess: jsonb("sess").notNull(),
    expire: timestamp("expire").notNull(),
  },
  (table) => [index("IDX_session_expire").on(table.expire)],
);

// User storage table - Updated for Replit Auth
export const users = pgTable("users", {
  id: varchar("id").primaryKey().default(sql`gen_random_uuid()`),
  email: varchar("email").unique(),
  firstName: varchar("first_name"),
  lastName: varchar("last_name"),
  profileImageUrl: varchar("profile_image_url"),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
});

export const upsertUserSchema = createInsertSchema(users).omit({
  createdAt: true,
  updatedAt: true,
});

export type UpsertUser = z.infer<typeof upsertUserSchema>;
export type User = typeof users.$inferSelect;

// Projects table - Groups images and edits into projects
export const projects = pgTable("projects", {
  id: serial("id").primaryKey(),
  userId: varchar("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  name: varchar("name"),
  createdAt: timestamp("created_at").defaultNow(),
}, (table) => [
  index("projects_user_id_idx").on(table.userId),
  index("projects_user_id_created_at_idx").on(table.userId, table.createdAt.desc()),  // ← NEW
]);

export const insertProjectSchema = createInsertSchema(projects).omit({
  id: true,
  createdAt: true,
});

export type InsertProject = z.infer<typeof insertProjectSchema>;
export type Project = typeof projects.$inferSelect;

// Images table - Stores uploaded images and their metadata
export const images = pgTable("images", {
  id: serial("id").primaryKey(),
  userId: varchar("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  projectId: integer("project_id").references(() => projects.id, { onDelete: "cascade" }),
  parentImageId: integer("parent_image_id").references((): any => images.id, { onDelete: "cascade" }),
  isOriginal: integer("is_original").notNull().default(1),
  originalUrl: text("original_url").notNull(),
  currentUrl: text("current_url").notNull(),
  fileName: varchar("file_name").notNull(),
  fileSize: integer("file_size").notNull(),
  width: integer("width").notNull(),
  height: integer("height").notNull(),
  createdAt: timestamp("created_at").defaultNow(),
  updatedAt: timestamp("updated_at").defaultNow(),
}, (table) => [
  index("images_user_id_idx").on(table.userId),
  index("images_project_id_idx").on(table.projectId),
  index("images_parent_id_idx").on(table.parentImageId),
  index("images_user_id_created_at_idx").on(table.userId, table.createdAt.desc()),  // ← NEW
  index("images_project_id_created_at_idx").on(table.projectId, table.createdAt.desc()),  // ← NEW
]);

export const insertImageSchema = createInsertSchema(images).omit({
  id: true,
  createdAt: true,
  updatedAt: true,
});

export type InsertImage = z.infer<typeof insertImageSchema>;
export type Image = typeof images.$inferSelect;

// Edits table - Stores edit history for images
export const edits = pgTable("edits", {
  id: serial("id").primaryKey(),
  imageId: integer("image_id").notNull().references(() => images.id, { onDelete: "cascade" }),
  userId: varchar("user_id").notNull().references(() => users.id, { onDelete: "cascade" }),
  prompt: text("prompt").notNull(),
  resultUrl: text("result_url").notNull(),
  savedImageId: integer("saved_image_id").references(() => images.id, { onDelete: "set null" }),
  createdAt: timestamp("created_at").defaultNow(),
}, (table) => [
  index("edits_image_id_idx").on(table.imageId),
  index("edits_user_id_idx").on(table.userId),
  index("edits_saved_image_id_idx").on(table.savedImageId),
  index("edits_image_id_created_at_idx").on(table.imageId, table.createdAt.desc()),  // ← NEW
  index("edits_user_id_created_at_idx").on(table.userId, table.createdAt.desc()),  // ← NEW
]);

export const insertEditSchema = createInsertSchema(edits).omit({
  id: true,
  createdAt: true,
});

export type InsertEdit = z.infer<typeof insertEditSchema>;
export type Edit = typeof edits.$inferSelect;





SUMMARY OF CHANGES

5 new composite indexes added:

1.
projects_user_id_created_at_idx - Projects sorted by date

2.
images_user_id_created_at_idx - User's images sorted by date

3.
images_project_id_created_at_idx - Project's images sorted by date

4.
edits_image_id_created_at_idx - Edit history sorted by date (most important!)

5.
edits_user_id_created_at_idx - User's edits sorted by date

Key points:

•
✅ All indexes use .desc() to match ORDER BY created_at DESC queries

•
✅ Existing indexes are kept (no breaking changes)

•
✅ Composite indexes eliminate separate sort operations

•
✅ Future-proof: Will scale well with data growth
