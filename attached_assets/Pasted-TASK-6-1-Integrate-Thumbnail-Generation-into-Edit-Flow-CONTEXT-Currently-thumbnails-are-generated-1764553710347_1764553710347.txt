TASK 6.1: Integrate Thumbnail Generation into Edit Flow

CONTEXT

Currently thumbnails are generated for:

•
✅ New uploads (Task 5.1 completed)

•
❌ AI edits (NOT YET)

When user edits an image with AI, a new image record is created with the edited result. This new image also needs a thumbnail for the gallery.

GOAL

Add thumbnail generation to the edit flow, so edited images automatically get thumbnails.

IMPLEMENTATION

Find Edit Endpoint

File: server/routes.ts

Search for: POST /api/images/:id/edit or similar edit endpoint

Look for code that creates new image after edit:

TypeScript


const editedImage = await storage.createImage({
  userId: req.user!.id,
  projectId: originalImage.projectId,
  parentImageId: imageId,
  isOriginal: 0,
  originalUrl: editResult.url,  // ← Edited image URL
  currentUrl: editResult.url,
  // ...
});

return res.json({ success: true, image: editedImage });


Add Thumbnail Generation

Add after createImage and before return:

TypeScript


const editedImage = await storage.createImage({
  userId: req.user!.id,
  projectId: originalImage.projectId,
  parentImageId: imageId,
  isOriginal: 0,
  originalUrl: editResult.url,
  currentUrl: editResult.url,
  // ...
});

// Generate thumbnail for edited image (fire-and-forget)
generateThumbnailInBackground(editedImage.id, editedImage.originalUrl)
  .catch(err => console.error('[Edit] Thumbnail generation failed:', err));

return res.json({ success: true, image: editedImage });


Verify Import

Make sure generateThumbnailInBackground is imported at the top of the file:

TypeScript


import { generateThumbnailInBackground } from './thumbnailHelpers';

NOTES

Fire-and-Forget Pattern

Same as upload flow - thumbnail generation doesn't block the edit response:

TypeScript


generateThumbnailInBackground(...)
  .catch(err => console.error(...));  // ← Don't await, don't throw

return res.json(...);  // ← Returns immediately


Edit vs Upload

•
Upload: Uses generateUploadThumbnail() internally

•
Edit: Also uses generateUploadThumbnail() (works for both!)

•
Both save thumbnails to /.private/uploads/{id}/thumb.webp

Why This Works

The generateThumbnailInBackground helper:

1.
Extracts upload ID from path

2.
Downloads original from GCS

3.
Generates WebP thumbnail with .rotate()

4.
Uploads to /.private/uploads/{id}/thumb.webp

5.
Updates database with /objects/uploads/{id}/thumb.webp

Works for both uploads and edits!

EDGE CASES

What if edit fails?

Edit fails → No new image created → No thumbnail generation triggered → ✅ OK

What if thumbnail generation fails?

Thumbnail fails → Error logged → Gallery uses fallback to original → ✅ OK

What if user edits multiple times?

Each edit creates new image → Each gets thumbnail → ✅ OK
