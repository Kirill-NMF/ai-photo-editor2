PROBLEM

Symptoms:

•
New edits show full-size images in Edit History (not thumbnails)

•
Even though thumbnails are generated successfully on server

•
Database is updated correctly with thumbnailUrl

•
Frontend never sees the updated data

Root cause (from Architect analysis):

1.
Edit created → Response has thumbnailUrl = null (immediate)

2.
Background worker → Generates thumbnail and updates DB (1-2 seconds later)

3.
Frontend → Never refetches data after background job completes

4.
EditorCache (localStorage) → Saves stale data with thumbnailUrl = null

5.
Result → User sees full-size images forever




SOLUTION

Auto-refetch edit data 2 seconds after creation to pick up the generated thumbnailUrl.

Flow:

Plain Text


1. User creates edit
   ↓
2. Server returns edit with thumbnailUrl = null
   ↓
3. Frontend displays edit (shows full-size via fallback)
   ↓
4. Background worker generates thumbnail (1-2 sec)
   ↓
5. Frontend auto-refetches after 2 seconds ← NEW!
   ↓
6. Frontend receives updated edit with thumbnailUrl
   ↓
7. UI updates to show thumbnail ✅

Add auto-refetch logic:

TypeScript


const createEditMutation = useMutation({
  mutationFn: async (prompt: string) => {
    const response = await fetch(`/api/edits`, {
      method: 'POST',
      body: JSON.stringify({ imageId, prompt, baseEditId }),
    });
    return response.json();
  },
  onSuccess: (data) => {
    // Immediate invalidation (gets edit with thumbnailUrl = null)
    queryClient.invalidateQueries(['edits', imageId]);
    
    // Schedule refetch after 2 seconds to get generated thumbnail
    setTimeout(() => {
      console.log('[EditorPage] Refetching edits to get generated thumbnails');
      queryClient.invalidateQueries(['edits', imageId]);
    }, 2000);
  }
});


Why 2 seconds?

•
Thumbnail generation takes ~1 second on average

•
2 seconds gives buffer for slower cases

•
Not too long to annoy user

•
User won't notice the delay (thumbnail appears smoothly)

  queryKey: ['edits', imageId],
  queryFn: () => fetchEdits(imageId),
});

// Update EditorCache when edits change
useEffect(() => {
  if (edits && edits.length > 0) {
    console.log('[EditorPage] Updating EditorCache with fresh data');
    editorCache.updateEdits(imageId, edits);
  }
}, [edits, imageId]);


In editorCache.ts, add update method:

TypeScript


export const editorCache = {
  // ... existing methods

  /**
   * Update cached edits with fresh data from server
   * Merges with existing cache to preserve local state
   */
  updateEdits(imageId: number, freshEdits: Edit[]) {
    const cacheKey = `photo_editor_state_${imageId}`;
    const existing = this.load(imageId);
    
    if (!existing) {
      // No cache yet, save fresh data
      this.save(imageId, { edits: freshEdits });
      return;
    }
    
    // Merge fresh data with existing cache
    const mergedEdits = freshEdits.map(freshEdit => {
      const cachedEdit = existing.edits.find(e => e.id === freshEdit.id);
      
      // Use fresh data (especially thumbnailUrl) but preserve any local state
      return {
        ...cachedEdit,
        ...freshEdit,
        // thumbnailUrl from server takes priority
        thumbnailUrl: freshEdit.thumbnailUrl || cachedEdit?.thumbnailUrl,
      };
    });
    
    this.save(imageId, {
      ...existing,
      edits: mergedEdits,
    });
    
    console.log('[EditorCache] Updated cache with fresh thumbnailUrls');
  },
};





Step 3: Ensure React Query refetches correctly

File: client/src/pages/EditorPage.tsx

Make sure query is configured to refetch:

TypeScript


const { data: edits } = useQuery({
  queryKey: ['edits', imageId],
  queryFn: () => fetchEdits(imageId),
  staleTime: 0,  // Always consider data stale (allows refetch)
  refetchOnMount: true,  // Refetch when component mounts
});


Why staleTime: 0?

•
Ensures invalidateQueries actually triggers a refetch

•
Without this, React Query might use cached data

•
We want fresh data to get updated thumbnailUrl

EDGE CASES

What if thumbnail generation fails?

•
Edit stays with thumbnailUrl = null

•
Fallback shows full-size image

•
No error shown to user (graceful degradation)

What if user navigates away before refetch?

•
Refetch still happens in background

•
Next time user opens editor, data is fresh

•
EditorCache has updated thumbnailUrl

What if network is slow?

•
2 second delay might not be enough

•
User sees full-size for longer

•
Eventually refetch happens (React Query retries)

•
Consider increasing delay to 3 seconds if needed
